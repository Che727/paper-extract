# Paper Extract — 论文 AI 提取 + 组会研究追踪

> 两个 Claude Code Skill，组成「论文阅读 → 组会讨论 → 论文写作」研究闭环。

## 这是什么

做学术研究时，我们面临两个痛点：

1. **论文太多**：几十篇 PDF，每篇手动做笔记、分类、标注，读完就忘
2. **组会太密**：每周导师的意见、布置的任务、研究方向的修正，散落在聊天记录和文档里，缺乏系统追踪

这两个 Skill 分别解决这两个问题，并且**互相联动**——论文阅读的成果自动关联到组会讨论，组会布置的检索任务闭环到论文入库。

```
paper-extract                          meeting-extract
┌──────────────────────┐          ┌──────────────────────────┐
│ PDF → AI提取 → 论文表  │  讨论论文  │ Wiki → AI提取 → 组会表      │
│                      │◄──关联──►│                          │
│  元信息 + 14个内容维度  │          │  TODO追踪 + 方向演进 +     │
│  标签+详情配对         │          │  导师评价沉淀              │
└──────────────────────┘          └──────────────────────────┘
        论文管理                         研究追踪
```

## paper-extract：论文 AI 提取

### 核心功能

- **上传即提取**：PDF 上传到飞书表格 → AI 自动提取元信息 + 14 个内容维度
- **标签+详情双字段**：每个维度配有标签（多选，快速筛选）和详情（Markdown，深入阅读），例如「方法标签」筛选 POE + AHP → 找到所有用了这两种方法的论文
- **同义词自动去重**：创建标签时智能复用已有选项，避免"POE"和"使用后评价"并存
- **三级 PDF 降级**：pdfplumber → PyMuPDF → OCR skill，兼容标准 PDF、结构异常 PDF、扫描版 PDF
- **断点续传**：提取中断后重跑自动跳过已完成字段

### 论文阅读方法论

提取框架基于导师论文阅读方法论——**鱼头-鱼身-鱼尾**：

```
🎯 鱼头：核心研究问题 + 子问题链
     ↓
🔬 鱼身：研究方法（数据来源/样本量/技术路线/案例选择）
     ↓
📊 鱼尾：核心结论（严格区分「现状描述」vs「研究结论」）
```

8 条质量红线：

1. ❌ 混淆研究目标与核心问题——「研究了什么」≠「解决了什么根本痛点」
2. ❌ 把背景信息当成结论——现象描述不是研究贡献
3. ❌ 标签化表述——不能说「设施不足」，要说「缺什么、缺多少、为什么缺」
4. ❌ 跳过分析直接给结论——论文有完整的逻辑链，阅读也要还原它
5. ❌ 只会复述不会判断——必须明确说「哪里好、为什么好」
6. ❌ 为复杂方法喝彩——工具复杂 ≠ 有价值
7. ❌ 囫囵吞枣——要穿透到论文的逻辑骨架
8. ❌ 脱离自己论文泛泛而读——每一处分析都要问「这对我有什么用」

### PDF 三级降级策略

| 级别 | 工具 | 适用场景 | 成功率 |
|------|------|---------|--------|
| 1 | pdfplumber | 标准 PDF，文字层完好 | 90%+ |
| 2 | PyMuPDF (fitz) | PDF 结构异常但文字层存在 | 8% |
| 3 | pdf-ocr-extraction skill | 扫描版/图片型 PDF | 2% |

## meeting-extract：组会研究追踪

### 核心功能

- **结构化提取**：从飞书 Wiki 组会记录中自动提取议题、导师意见、研究方向变化、TODO 任务
- **前后会议串联**：自动关联上一次组会，追踪 TODO 完成情况（✅ 完成 / ⚠️ 部分 / ❌ 未开始）
- **论文自动匹配**：从会议内容中识别讨论的论文 → 在论文表中搜索匹配 → 自动设置双向关联
- **导师评价沉淀**：组会中对论文的点评自动回写到论文表的「导师评价」字段
- **研究方向演进追踪**：记录每次方向变化（四维协同 → 运营视角 → POE 聚焦），形成研究脉络

### 飞书表格字段方案

采用与论文表一致的「标签(多选) + 详情(多行文本)」配对模式：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 快捷标签 | 自动编号 | MTG-001, MTG-002... |
| 会议日期 | 日期 | YYYY-MM-DD |
| 会议标题 | 文本 | 核心议题概括，如「方向修正：运营视角→POE聚焦」 |
| 重要程度 | 单选 | ⭐ 关键转折 / 重要进展 / 常规组会 |
| 会议类型 | 单选 | 常规组会 / 开题答辩 / 中期答辩 / 预答辩 |
| 🔗 上次组会 | 关联记录(自身) | 指向上一会议，形成完整链条 |
| **核心议题标签** | 多选 | 方向修正/论文框架/案例选择/文献检索/方法讨论/写作规范/时间节点/理论梳理 |
| 核心议题详情 | 多行文本 | 本次核心学术问题概述 |
| **导师意见标签** | 多选 | 方向调整/理论精简/方法建议/案例指导/写作红线/范围收缩/标题打磨/量化要求 |
| 导师意见详情 | 多行文本 | 老师关键指导 |
| 研究方向变化 | 多选 | 记录方向演进（如：四维协同→运营视角→POE聚焦） |
| 方法论变化 | 多选 | 记录方法引入（如：AHP→POE→大数据） |
| **本次TODO标签** | 多选 | 文献检索/框架搭建/理论梳理/案例调研/标题打磨/数据处理/政策梳理/格式调整/汇报准备 |
| 本次TODO详情 | 多行文本 | 具体任务描述 |
| **上次TODO完成情况标签** | 多选 | 全部完成/部分完成/未完成/方向变更已废弃 |
| 上次TODO完成情况详情 | 多行文本 | ✅/⚠️/❌ 逐条标注完成状态 |
| **关键决策标签** | 多选 | 方向锁定/标题确定/方法确定/案例确定/理论确定/结构确定/范围确定 |
| 关键决策详情 | 多行文本 | 本次定论性决策 |
| 🔗 讨论论文 | 关联记录(论文表) | 匹配本次讨论的论文 |
| 研究阶段 | 单选 | 按研究演进划分的 Era 阶段 |
| 原始记录链接 | URL | 飞书 Wiki 原文 |
| 我的笔记 | 多行文本 | 自由批注 |

### 前后组会串联机制

```
MTG-005 (2026.05.20)
  📋 本次TODO: ①检索文献 ②找分类依据 ③搭框架
         ↓ 两周后
MTG-006 (2026.06.03)
  📌 上次TODO完成情况:
     ✅ ②分类依据 — 找到了
     ⚠️ ③框架 — 只搭了一级标题
     ❌ ①文献检索 — 未完成
  📋 本次TODO: ①细化框架 ②换关键词重搜文献
```

筛选「上次TODO完成情况标签 = 未完成」，可立即看到所有遗留任务。

## 两表联动

paper-extract 和 meeting-extract 通过**关联记录**实现双向联动：

| 联动点 | 说明 |
|--------|------|
| **论文-组会双向关联** | 组会表「讨论论文」↔ 论文表「讨论组会」，点击可互相跳转 |
| **研究方向动态同步** | meeting-extract 捕获方向变化 → paper-extract 的「对我论文的借鉴」自动跑在最新方向下 |
| **导师评价沉淀** | 组会对论文的点评自动回写论文表，按会议编号累积 |
| **TODO → 论文闭环** | 组会布置「检索XX方向论文」→ 找到后上传论文表 → 关联回组会 TODO |

## 快速开始

### 1. 环境要求

- Python 3.10+
- Node.js 22+（飞书 CLI 依赖）
- 飞书开放平台应用（需 Base、Drive 权限）
- Claude Code（推荐）或 Anthropic API Key

### 2. 安装依赖

```bash
# Python PDF 处理
pip install pdfplumber PyMuPDF python-dotenv

# 飞书 CLI
npm install -g @larksuite/cli
npx skills add larksuite/cli -y -g
```

### 3. 配置飞书 CLI

```bash
lark-cli config init --app-id <your_app_id> --app-secret-stdin
lark-cli auth login --recommend
```

### 4. 创建飞书多维表格

在飞书开放平台创建 Base，按上述字段方案分别创建「论文阅读」表和「组会记录」表。两张表必须在**同一个 Base** 下（否则关联记录无法跨 Base）。

> 建议直接复制字段方案中的表格，使用 `lark-cli base +table-create` 命令创建。两个 skill 文件中的字段设计可作为 `--fields` JSON 参数参考。

### 5. 安装 Skill

```bash
git clone https://github.com/Che727/paper-extract.git
cp paper-extract/.claude/skills/meeting-extract.md ~/.claude/skills/
```

### 6. 配置 Skill

使用前需修改 skill 文件中的飞书配置（Base Token、Table ID、Wiki Space ID）。详见各 skill 文件头部的「飞书表格信息」和「配置清单」章节。

paper-extract 首次运行时还会询问你的研究背景，后续自动用于论文借鉴分析。

### 7. 使用

```bash
# 论文提取
/paper-extract <record_id>          # 处理指定论文
开始总结论文                         # 处理最新未提取的论文

# 组会提取
/meeting-extract <wiki_url>          # 处理指定组会记录
/meeting-extract --all                # 批量处理未提取的组会
```
