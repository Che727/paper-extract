# meeting-extract

> 与 [paper-extract](paper-extract.md) 配套使用，组成「论文阅读 → 组会讨论 → 论文写作」研究闭环。

## 描述

从飞书 Wiki 组会记录中自动提取结构化信息，写入飞书多维表格「组会记录」。自动关联上次组会的 TODO 完成情况、匹配讨论的论文到论文阅读表，实现组会表与论文表的双向联动。

## 与 paper-extract 的联动关系

```
paper-extract（输入端）              meeting-extract（加工端）
┌──────────────────────┐          ┌──────────────────────────┐
│ PDF → AI提取 → 论文表  │          │ Wiki → AI提取 → 组会表      │
│                      │  讨论论文  │                          │
│ 论文表 ◄─────────────┼──关联─────┼─ 组会表.讨论论文           │
│   .讨论组会           │          │   .本次TODO               │
│   .导师评价标签        │          │   .上次TODO完成情况         │
│   .导师评价详情        │          │   .研究方向变化            │
└──────────────────────┘          └──────────────────────────┘
        ↑                                    │
        │     研究方向上下文注入               │
        └────────────────────────────────────┘
        paper-extract 读取组会表最新方向→影响「对我论文的借鉴」分析
```

**核心联动机制：**

1. **论文自动匹配**：meeting-extract 从会议内容中识别讨论的论文 → 在论文表中搜索匹配 → 自动设置双向关联（组会.讨论论文 ↔ 论文.讨论组会）
2. **研究方向同步**：组会表记录每次方向变化 → paper-extract 提取时读取最新方向作为上下文 → 「对我论文的借鉴」分析始终跑在最新研究方向下
3. **导师评价沉淀**：组会中导师对论文的点评 → 自动回写到论文表的「导师评价」字段，论文侧持续积累评价
4. **TODO 闭环**：组会布置的论文检索任务 → paper-extract 处理新论文时可标记来源 TODO → 下次组会追踪完成状态

## 触发方式

**触发词**：`/meeting-extract`、`提取组会`、`导入组会`

```
/meeting-extract <wiki_url>      # 处理指定组会记录
/meeting-extract --all            # 批量处理 Wiki 空间中所有未提取的组会
```

## 前置条件

- 飞书 CLI (`lark-cli`) 已安装并登录
- 组会 Wiki 空间中有组会文档（格式：`YYYY.MM.DD组会`）
- 论文阅读表已创建（参考 [paper-extract 字段方案](paper-extract.md)），且已新增联动字段（讨论组会 / 导师评价标签 / 导师评价详情）
- paper-extract skill 已完成初始配置

## 飞书表格信息

采用与论文表一致的「标签(多选) + 详情(多行文本)」配对模式：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 快捷标签 | 自动编号 | MTG-001, MTG-002... |
| 会议日期 | 日期 | YYYY-MM-DD |
| 会议标题 | 文本 | 核心议题概括，如「方向修正：运营视角→POE聚焦」 |
| 重要程度 | 单选 | ⭐ 关键转折 / 重要进展 / 常规组会 |
| 会议类型 | 单选 | 常规组会 / 开题答辩 / 中期答辩 / 预答辩 |
| 🔗 上次组会 | 关联记录(自身) | 指向上一次会议，形成 MTG-N → MTG-N+1 链条 |
| **核心议题标签** | 多选 | 方向修正/论文框架/案例选择/文献检索/方法讨论/写作规范/时间节点/理论梳理 |
| 核心议题详情 | 多行文本 | 本次讨论的核心学术问题概述 |
| **导师意见标签** | 多选 | 方向调整/理论精简/方法建议/案例指导/写作红线/范围收缩/标题打磨/量化要求 |
| 导师意见详情 | 多行文本 | 老师关键指导的精简摘要 |
| 研究方向变化 | 多选 | 记录每次研究方向的演进 |
| 方法论变化 | 多选 | 记录方法论的引入和变迁 |
| **本次TODO标签** | 多选 | 文献检索/框架搭建/理论梳理/案例调研/标题打磨/数据处理/政策梳理/格式调整/汇报准备 |
| 本次TODO详情 | 多行文本 | 导师布置的具体任务 |
| **上次TODO完成情况标签** | 多选 | 全部完成/部分完成/未完成/方向变更已废弃 |
| 上次TODO完成情况详情 | 多行文本 | 用 ✅/⚠️/❌ 逐条标注上次任务完成状态 |
| **关键决策标签** | 多选 | 方向锁定/标题确定/方法确定/案例确定/理论确定/结构确定/范围确定 |
| 关键决策详情 | 多行文本 | 本次会议做出的定论性决策 |
| 🔗 讨论论文 | 关联记录(论文表) | 匹配本次讨论的论文（多对多） |
| 研究阶段 | 单选 | 按论文研究演进划分的 Era 阶段 |
| 原始记录链接 | URL | 飞书 Wiki 原文链接 |
| 我的笔记 | 多行文本 | 自由批注 |

### 论文表配套新增字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 🔗 讨论组会 | 关联记录(组会表) | 反向关联，与组会表「讨论论文」双向自动生成 |
| **导师评价标签** | 多选 | 方法论优秀/案例匹配/可直接引用/需调整后用/参考价值有限 |

## 组会 Wiki 文档格式

组会记录保存在飞书知识空间中，文档类型为 `docx`，每篇命名格式为 `YYYY.MM.DD组会`，内容结构为：

- `【智能总结】` — AI 生成的会议摘要（核心提取来源）
- `【待办】` — 导师布置的具体任务列表
- `【原文】` — 原始语音转文字（含说话人标注）

提取时优先使用【智能总结】部分，【原文】作为补充。

## 工作流

### Step 1: 定位目标组会文档

**如果用户指定了 `<wiki_url>`：**
```bash
lark-cli wiki +node-get --node-token "<wiki_url>" --as user
```
从返回结果获取 `obj_token`（即 document_id）。

**如果用户指定了 `--all`：**
列出 Wiki 空间所有文档，筛选出未提取的：
```bash
lark-cli wiki +node-list --space-id <YOUR_WIKI_SPACE_ID> --as user --format json
```
对比组会表中已有记录的日期，找出未导入的文档，按日期升序处理。

---

### Step 2: 获取上次组会上下文（核心串联机制）

在组会表中按日期倒序查找最近一条记录，提取其 TODO 和关键决策作为上下文：

```bash
lark-cli base +record-list --base-token <YOUR_BASE_TOKEN> \
  --table-id <YOUR_MEETING_TABLE_ID> --as user --format json
```

从结果中取日期最新的一条记录，提取：
- `本次TODO详情` → 作为「上次组会的 TODO 列表」
- `关键决策详情` → 作为「上次组会的关键决策」

批量导入时按时间顺序逐条处理——每条记录处理时前面的记录已入库，天然形成上下文。

---

### Step 3: 获取论文表候选列表（论文匹配用）

参考 [paper-extract](paper-extract.md) 的表格信息，读取论文表中所有记录的标题、作者、关键词：

```bash
lark-cli base +record-list --base-token <YOUR_BASE_TOKEN> \
  --table-id <YOUR_PAPER_TABLE_ID> --as user --format json
```

整理成 AI 可匹配的候选列表。paper-extract 提取的论文越多，meeting-extract 的匹配精度越高。

---

### Step 4: 获取组会文档内容

```bash
lark-cli docs +fetch --doc <obj_token> --as user --api-version v2
```

从返回的 HTML 内容中提取纯文本。

---

### Step 5: AI 提取结构化信息

**System Prompt:**

```
你是学术会议记录结构化提取助手。你需要从组会记录中提取结构化信息，同时理解学术研究语境。

研究背景（根据实际论文方向配置）：
- 题目方向：<你的论文题目>
- 核心方法：<你的核心研究方法>
- 研究范围：<你的研究范围和案例>
- 当前阶段：<当前研究阶段和关键节点>

你需要理解学术指导语境：导师的意见、研究方向的变化、方法论的演进、TODO任务的分配与完成追踪。
```

**User Prompt:**

```
请从以下组会记录中提取结构化信息。以严格的 JSON 格式输出，不要输出任何其他内容。

## 上次组会上下文（用于识别 TODO 完成情况）
- 上次组会日期: <从Step 2获取>
- 上次TODO列表: <从Step 2获取的「本次TODO详情」>
- 上次关键决策: <从Step 2获取的「关键决策详情」>

## 可匹配的论文列表（用于识别讨论的论文）
<从Step 3获取的论文表所有记录的标题、作者、关键词>

## 输出格式
{

  "会议标题": "简短的会议核心议题概括，如「方向修正：运营视角→POE聚焦」",
  "会议类型": "常规组会",
  "重要程度": "常规组会",
  "核心议题标签": ["方向修正", "论文框架"],
  "核心议题详情": "本次讨论的1-3个核心学术问题概述，100-300字",

  "导师意见详情": "老师关键指导的精简摘要，保留核心判断和硬性要求。如无明确意见填'(无)'",
  "研究方向变化": [],

## 提取规则
1. **重要程度**：根据会议内容判断——研究方向重大转向/核心方法论确立/关键答辩 → "⭐ 关键转折"；重要概念成型/关键原则确立/重要范本确认 → "重要进展"；常规文献研读/进度检查 → "常规组会"
2. **会议标题**：提取最核心的议题作为标题，格式如「方向修正：运营视角→POE聚焦」，不要写日期
3. **TODO完成情况推断**：对比「上次TODO列表」和本次会议内容，当导师询问或学生汇报进度时推断。标注：✅ 明确完成 / ⚠️ 部分完成 / ❌ 未开始
4. **研究方向/方法论变化**：仅当本次会议明确提出修正时才填写，否则留空数组
5. **讨论论文匹配**：在论文列表中按标题、作者、关键词模糊匹配——如「沈建大那篇POE论文」→ 找标题含「沈阳」「POE」的记录
6. **原始记录链接**和**上次组会关联**：在 Step 6 写入时自动填充，不需 AI 提取
7. 标签字段仅使用候选标签，不要自创。如确实没有匹配的标签，留空数组[]

## 会议原文
---
<飞书 Wiki 文档内容>
---
```

### Step 6: 写入组会表并回写论文表

将 AI 提取结果写入飞书表格。先检查组会表中是否已有该日期的记录（避免重复导入）。

#### 6a: 确定上次组会关联

在组会表中按日期倒序找到最近一条记录，取其 record_id，作为本次的「上次组会」关联值。

#### 6b: 确定讨论论文关联

对于 AI 返回的「讨论论文」列表中的每篇论文标题，在论文表中搜索匹配的记录，获取其 record_id。

#### 6c: 写入组会记录

```bash
lark-cli base +record-upsert --base-token <YOUR_BASE_TOKEN> \
  --table-id <YOUR_MEETING_TABLE_ID> --record-id <record_id_or_empty_for_new> \
  --json '{
    "会议日期": "2026-06-03",
    "会议标题": "<AI提取的标题>",
    "会议类型": "<AI提取的类型>",
    "重要程度": "<AI提取的重要程度>",
    "上次组会": ["<上次组会的record_id>"],
    "核心议题标签": [...],
    "核心议题详情": "<AI提取>",
    "导师意见标签": [...],
    "导师意见详情": "<AI提取>",
    "研究方向变化": [...],
    "方法论变化": [...],
    "本次TODO标签": [...],
    "本次TODO详情": "<AI提取>",
    "上次TODO完成情况标签": [...],
    "上次TODO完成情况详情": "<AI提取>",
    "关键决策标签": [...],
    "关键决策详情": "<AI提取>",
    "讨论论文": ["<论文表record_id_1>", "<论文表record_id_2>"],
    "研究阶段": "<AI提取>",
    "原始记录链接": "<飞书Wiki原文URL>"
  }' --as user
```

**注意**：`lark-cli base +record-upsert` 的 JSON 不要包裹在 `fields` 内（原始 field map 即可）。

#### 6d: 回写论文表（与 paper-extract 联动）

对每篇被讨论的论文，在其「导师评价详情」和「讨论组会」字段追加本次组会信息。参考 paper-extract 的写入方式（Step 5b），字段名替换为组会联动字段：

```bash
lark-cli base +record-upsert --base-token <YOUR_BASE_TOKEN> \
  --table-id <YOUR_PAPER_TABLE_ID> --record-id <论文record_id> \
  --json '{
    "讨论组会": ["<组会record_id>"],
    "导师评价标签": ["<导师评价标签>"],
    "导师评价详情": "### MTG-XXX (日期) 导师评价\n<本次组会对该论文的点评>"
  }' --as user
```

---

### Step 7: 处理完成后

告知用户：
- 处理了哪次组会
- 提取的关键信息摘要（核心议题 + 导师意见要点）
- 关联了哪几篇论文
- 上次 TODO 完成情况
- Token 消耗统计
- 提示去飞书表格复核

## 批量导入（--all）流程

```bash
# 1. 获取 Wiki 空间所有文档
lark-cli wiki +node-list --space-id <YOUR_WIKI_SPACE_ID> --as user --format json

# 2. 获取组会表已有记录（按日期去重）
lark-cli base +record-list --base-token <YOUR_BASE_TOKEN> \
  --table-id <YOUR_MEETING_TABLE_ID> --as user --format json

# 3. 找出未导入的文档，按日期升序排列

# 4. 逐条处理（按时间顺序，确保「上次组会」上下文正确）：
#    for each 未导入文档:
#      Step 2: 获取上次组会上下文（此时前面导入的已在表中）
#      → Step 4: 获取文档内容
#      → Step 5: AI 提取
#      → Step 6: 写入组会表 + 回写论文表
```

## 失败处理

### 文档内容过短
如果 docs +fetch 返回内容 < 200 字符，可能是空文档或格式异常，跳过并标记。

### 重复导入
写入前检查组会表中是否已有相同日期的记录，如有则提示用户是否覆盖。

### AI 提取质量不足
如果 AI 返回的 JSON 中关键字段（会议日期、会议标题、本次TODO详情）为空，标记为需人工复核。

### 论文匹配失败
如果「讨论论文」中 AI 返回的论文标题在论文表中找不到匹配记录，标记为「待确认」并提示用户手动关联。

## 配置清单

开始使用前请完成以下配置：

1. **飞书 Base 和 Table**：在飞书开放平台创建 Base，按上述字段方案创建组会表和论文表
2. **论文表联动字段**：在已有论文表中新增「讨论组会」「导师评价标签」「导师评价详情」三个字段
3. **Wiki 空间**：确认组会记录所在的知识空间 ID
4. **paper-extract**：确保 paper-extract skill 已配置完成（同一 Base 下的论文表）
5. **研究背景**：在 System Prompt 中填入你的具体研究方向
